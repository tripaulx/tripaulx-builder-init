# Registro de incidentes

> **Modelo.** Esta página define a política. Mantenha cada registro em local controlado (repositório ou documento restrito), a partir do modelo de registro de incidente.

**Responsável:** {{ dpo_name }} · **Última revisão:** {{ effective_date }}

## 1. Política

- **Todo** incidente de segurança é registrado, inclusive os que não exigiram comunicação. O registro é a prova de que {{ company }} avaliou cada evento.
- O registro é aberto na detecção, não no fim, e é atualizado durante a resposta.
- Os registros são guardados por pelo menos **5 anos**.
- O acesso é limitado ao líder do incidente, ao encarregado e à direção.
- Os registros contêm o mínimo de dados pessoais necessário. Sempre que possível, refira-se às pessoas pelo papel ou por um identificador interno.

## 2. Identificador

Use `INC-AAAA-NNN`, por exemplo `INC-2025-001`, sequencial dentro do ano.

## 3. Conteúdo mínimo

| Campo | Descrição |
|---|---|
| ID | `INC-AAAA-NNN` |
| Detectado em | Data e hora (com fuso) e por quem |
| Gravidade | Crítico, Alto, Médio ou Baixo (veja o plano de resposta) |
| Descrição | O que aconteceu, em palavras simples |
| Dados e pessoas afetados | Categorias e número aproximado |
| Sistemas | Componentes e fornecedores envolvidos |
| Linha do tempo | Principais fatos com data e hora |
| Contenção e recuperação | Ações tomadas e quando |
| Avaliação de risco | Probabilidade de dano às pessoas e por quê |
| Comunicações | Autoridade, pessoas e clientes: data, ou motivo para não comunicar |
| Causa raiz | Definida após a investigação |
| Lições e ações | Vínculos com a matriz de riscos e o backlog |
| Encerrado em | Data e quem aprovou o encerramento |
